# Spec: 课影 CourseCast MVP

Status: ready-for-agent
Source: docs/PRD-MVP.md（v0.5，已评审基线）· docs/VERIFICATION-2026-10-24.md

## Problem Statement

教师做微课/慕课的现状是录屏 → 念稿 → 剪辑 → 导出：一条 10 分钟的课平均耗 2–3 小时，且必须一次念对，念错整段重来。现有替代方案各有硬伤：纯 TTS + 录屏没有出镜感；真人出镜要背稿、重录成本高；商用数字人按分钟计费且形象不是本人；手动剪辑有学习成本、不能批量。念稿这一步占掉了制作时间的大头，却是最机械、最不该人来做的环节。

## Solution

教师只提供三样东西：课件（PDF 首选）、逐字稿、一段约 30–60 秒的本人出镜视频。课影把"念稿"彻底去掉：声音用本人音色克隆（MiMo voiceclone，实测 RTF 0.36），出镜画面循环使用那段通用素材并抠像成画中画，翻页点按逐字稿音频时长精确对齐（实测误差 ≤1 帧），最终由 ffmpeg 一次性合成单文件 MP4。人工操作 ≤6 步、≤5 分钟，无需剪辑知识；同时全部能力通过 MCP 工具与 `--json` CLI 暴露，AI 作为第一等用户可无人值守跑完全流程。交付形态是单文件 Windows 安装包，用户不需要装 Python / Node / ffmpeg。

## User Stories

1. 作为教师，我想新建项目并命名、选输出分辨率，所以多门课互不混淆
2. 作为教师，我想重启应用后项目进度不丢，所以不必一次做完
3. 作为教师，我想删除不要的项目，所以项目列表保持干净
4. 作为教师，我想直接拖入 PDF 就得到全部页图，因为"另存为 PDF"是我在 PowerPoint 里顺手的一步
5. 作为教师，我想拖入 pptx 也能用（本机 Office 转换），失败时明确提示"请先另存为 PDF"，所以不会被卡死在第一步
6. 作为教师，我想看到每页缩略图网格，所以能确认页数与顺序对不对
7. 作为学生观众，我希望页面顺序与课件页码一致，不出现第 10 页排在第 2 页前面
8. 作为教师，我想整段粘贴讲稿并用 `---` 或 `第N页` 自动切分映射到页，所以不用逐页搬运
9. 作为教师，我想在缩略图旁逐页填写讲稿，所以页数少时更直观
10. 作为教师，我想从 PPT 备注一键导入讲稿，所以写在备注里的稿子不用重打
11. 作为教师，页数与段落数不匹配时，我想要"自动均分 + 手动拖拽调整"的修正界面，而不是报错
12. 作为教师，某页没写讲稿时，我想它按 5 秒静默处理并标黄提醒，所以流程不中断
13. 作为教师，我想填入 MiMo API Key、上传参考音频（手机录音 m4a 也直接收）并试听克隆效果，所以确认声音像我本人
14. 作为教师，没有 Key 时我想自动降级到兜底音色且有明确提示条，所以全流程不中断
15. 作为教师，我想被要求勾选《声音授权确认》后才能生成，所以合规风险由明确的确认动作兜住
16. 作为教师，我想上传 ≤60 秒的出镜视频并自动抠像，看棋盘格上的边缘预览，所以发丝、手指有没有破洞我肉眼可查
17. 作为教师，抠像失败或我不想抠时，我想要"纯色圆角卡片"包住原视频，所以照样能出片
18. 作为教师，我想选人像位置（右下/左下/右侧竖条）、宽度、形状和翻页动效，所以成片风格合我的意
19. 作为教师，我想看到四段进度（合成语音 → 拼接音轨 → 处理人像 → 渲染成片），任一段失败可单独重试，所以不用从头跑
20. 作为教师，我想内嵌播放器预览成片并下载 MP4
21. 作为学生观众，我希望翻页点与讲解内容对齐（误差 ≤200 ms），人像不遮挡课件正文
22. 作为教师，我改了第 7 页讲稿后重新生成，成片里第 7 页的声音必须是重配的，所以不会出现新画面配旧声音
23. 作为教师，我中断后重进项目，已完成的阶段不重跑，所以改一个字不用等全片重做
24. 作为 AI 助手，我想通过工具查询项目当前阶段与缺失项，所以决定下一步靠返回值而不是猜
25. 作为 AI 助手，我想每个阶段都是可单步调用的工具（可指定页码），所以第 7 页配音不满意只重跑第 7 页
26. 作为 AI 助手，我想工具返回结构化 JSON（含产物路径与 `next` 建议），所以能自主串起全流程
27. 作为 AI 助手，我想重复调用结果一致（重跑前先查已落盘产物），所以不会重复烧 API 额度
28. 作为 AI 助手，TTS 返回 401 时我想被引导让用户填 Key，而不是擅自换兜底音色
29. 作为开发者，我想用 CLI 全部子命令的 `--json` 输出跑通全流程，所以 UI 之前就能验证管道、MCP 卡住时 CLI 能顶上
30. 作为 AI 助手，我想状态全部落在人可读的文件里（project.json / script.md），所以我能直接读改而不用绕 API

## Implementation Decisions

- **技术栈与平台**：Rust + Tauri 2，前端 Vue 3 + Element Plus（Tauri frontendDist，无路由库，6 步单页状态机）；**MVP 仅 Windows x64**——五条依赖链里只有 Windows 是完整闭环。
- **Cargo workspace 四 crate**：`cc-core`（业务核心，无 UI 无协议、可单测）/ `cc-cli`（全子命令 `--json`）/ `cc-mcp`（rmcp，stdio transport）/ `cc-app`（Tauri 壳）。**业务逻辑只有一份，三个壳都是薄包装**——UI 走的路和 AI 走的路必须是同一条。
- **文件即真相**：项目状态、逐字稿、版式全部落为人可读文件（JSON/Markdown/TOML），不用数据库；AI 直接读改文件后触发重跑。
- **状态机**（来自验证报告定稿）：`created → parsing → parsed → tts_running → tts_done → matte_running → matte_done → rendering → done`，任一阶段可进 `failed`（记录 stage + 错误信息）；只允许状态机定义的边，非法迁移报错。
- **输入指纹模型**：每个阶段的成功状态绑定 `input_fingerprint` + `tool_version` + 产物清单 + `depends_on`。tts **按页**指纹（该页文本 + 引擎 + 模型名 + 参考音频哈希 + 风格指令 + 语速参数）；matte 指纹 = 视频哈希 + 模型哈希 + downsample_ratio；render 指纹 = timeline 指纹 + 版式参数 + ffmpeg 版本 + 编码参数。失效传播：改第 7 页讲稿 → 第 7 页音频 → 整轨 → 成片，人像不受影响；改版式 → 只有成片失效。
- **并发**：项目级文件锁（独占句柄、进程退出自动释放）；project.json 原子写（tmp → fsync → rename）。
- **课件渲染（只渲染不解析）**：PDF 走 pdfium（BSD-3，预编译动态库随包分发，不用带 V8 的版本）；PPTX 在 Windows 走 PowerPoint COM，失败提示另存为 PDF；图片文件夹按文件名数字排序（禁止字符串排序）；按宽度 1920 等比出图，高度不足白底 pad，不拉伸。
- **TTS 主引擎（已实测）**：MiMo `mimo-v2.5-tts-voiceclone`，端点为 OpenAI 兼容 chat/completions，`api-key` 头鉴权；待念文本放 `role: assistant` 消息，`role: user` 放风格指令（可留空）；参考音频以 `data:audio/wav;base64,…` data URI 内联传入，**每次请求都要带**，编码后的 URI 在内存缓存；返回 24kHz / 单声道 / pcm_s16le wav。参考音频入库统一转 24kHz 单声道 wav（m4a 自动转码，实测 6 秒样本可用）；每页请求带超时（120 s）+ 重试（已观测到单次 64.6 s 异常慢请求）。
- **三级降级链**：MiMo（有 Key）→ edge-tts → Windows SAPI（完全离线）。edge-tts 是逆向的非官方接口、国内已有被阻断的报告，SAPI 是真正底线。降级发生时 UI 有明确提示条。
- **抠像**：推理后端封装为 trait 以便切换。当前基线 RVM MobileNetV3（⚠️ GPL-3.0，闭源分发前必须三选一：产品开源 / 换 Apache-2.0 的 MODNet 并加时域平滑 / 商业授权——**W1 拍板，切换只影响 trait 的实现与时间预算**）。参数：512 宽推理、alpha 上采样回原分辨率（不要把 1080p 直接喂模型，差 18 倍耗时）；逐帧推进时序状态；输出 ProRes 4444 保 alpha；后处理 despill + 1px 腐蚀去白边。抠像失败或跳过时兜底为纯色圆角卡片包原视频。
- **时间轴唯一公式**（来自 timeline spike 实测验证）：设第 i 页音频时长 d_i、页间静音 g = 0.6 s、共 N 页——第 i 页画面时长 = d_i + g（i < N）；第 N 页画面时长 = d_N（末页不加 g）；总时长 T = Σd_i + (N-1)·g。画面时长与音轨必须共用同一个 g；空白讲稿页的 5 秒计入 d_i。
- **合成**：ffmpeg 单次调用——concat 图片轨（每页 duration 按公式；末尾重复最后一张图，并以 `-t {T}` 硬锁总时长）、concat 音频滤镜拼音轨（页间 0.6 s 静音、末尾 1.0 s 淡出）、`-stream_loop -1` 循环人像 alpha 轨叠加画中画；H.264 + AAC，`+faststart`。翻页动效默认硬切，可选每页独立 fade 到白底（0.3 s）——不用 xfade 串链。
- **MCP 工具面**：`project_create / project_list / project_status / project_delete / slide_render / script_get / script_set / script_import_notes / voice_configure / voice_synthesize / person_matte / person_status / person_matte_skip / layout_set / render / artifact_clean`；全部返回结构化 JSON（含 ok、stage、产物路径、`next` 建议）。权限边界：路径 canonicalize 后校验在项目根内；项目 ID 限定 `[a-z0-9]{8,32}`；ffmpeg 一律参数数组调用，绝不拼 shell 字符串；API Key 只存 Windows Credential Manager，不进 project.json、不进日志、不进工具返回值；`artifact_clean` / `project_delete` 等不可逆操作需显式 `confirm: true`。
- **幂等性诚实边界**：TTS 已计费但响应丢失时本地无法确认服务端状态——重试前先查已落盘产物，无法确认时提示可能重复计费，不承诺绝不重复扣费。
- **分发**：自定义最小 ffmpeg 构建（只留 libx264 + aac + concat + overlay 等所需能力，目标单 exe ≤ 45 MB，不打包 ffprobe，时长从 wav 头解析）；pdfium.dll、ONNX 模型、ORT 运行时随包进 resources；安装包预算 ≤ 130 MB（估算 91 MB，W1 实测）。

## Testing Decisions

- **好测试只测外部行为**：CLI 子命令的 `--json` 输出、`project.json` 里的状态与指纹、产物文件本身（wav 时长、成片容器/视频/音轨三口径时长、翻页点位置），不测内部函数与私有结构。
- **两道缝**（与开发者确认过）：
  1. **主接缝 = `cc-cli` 端到端**：临时数据目录 + 真实 ffmpeg / ort，覆盖建项目 → 渲染 → 逐字稿 → 合成 → 抠像 → 成片的完整链路。UI 与 MCP 是同一 cc-core 的薄包装，测 CLI 即测用户与 AI 实际走的路径。
  2. **内部缝 = TTS 引擎 trait 的测试替身**：注入读 canned wav 的假引擎，管道测试离线、确定、不依赖 Key。真实 MiMo 引擎不进常规测试——其行为验证留在 `spikes/tts-test/`（实测基线：整体 RTF 0.36，输出 24kHz 单声道 wav）。
- **必测场景**：
  - 时间轴：5 页合成音频 + g=0.6 → 总时长 17.400 s 三口径一致、4 个翻页点误差 ≤ 33 ms（期望值直接沿用 timeline spike）；
  - 指纹失效传播：改第 7 页讲稿 → 仅 tts@第 7 页、整轨、成片重跑，matte 产物指纹不变不重跑；改版式 → 仅成片失效；
  - 降级链：无 Key → 自动落到兜底引擎、project.json 记录降级、返回 JSON 带提示；
  - 断点续跑：中断后重进，已完成阶段（指纹匹配）不重跑；
  - 状态机：非法迁移（如 parsed → rendering）报错且状态不变；
  - 并发：第二个进程拿不到项目锁，原子写无中间态；
  - 渲染冒烟：小页数真实 ffmpeg 出片，校验时长与翻页点；
  - 抠像冒烟：固定测试视频出 alpha 中间文件，校验尺寸与透明通道存在。
- **Prior art**：`spikes/` 下的四个验证脚本（timeline-test / perf-test / matte-bench / tts-test）就是行为级验证的雏形，其期望值与测试素材设计（如按亮度差设计翻页检测素材的教训）直接搬进正式测试。

## Out of Scope

- 口型同步 / 唇形驱动（V1.1 云端付费增强）
- 多机位、转场特效、花字动画；真 3D 卷页（已确认不做）
- 字幕烧录、背景音乐混音（均 V1.1）
- 账号体系、云端存储、多人协作；移动端 App
- macOS / Linux（延到 V1.1 独立排期）
- PPT 动画、切换效果、嵌入视频、演讲者视图（导出 PDF 本来就丢）
- 唱歌模式（voiceclone 模型不支持）
- 逐字稿"整段自动按页 AI 切分"（会引入 LLM 依赖与费用，MVP 不做——§12 Q3 建议，待最终拍板）
- 720p 提速档（渲染已 11.6x 实时，§12 Q2 建议砍掉，待最终拍板）
- 导出视频加水印（MVP 期不加）

## Further Notes

- **W1 未决项**（spec 不锁死实现，但要求拍板后才能冻结对应模块）：RVM 许可三选一（影响抠像模块与时间预算）；自定义最小 ffmpeg 构建实测体积；本机 MSVC 链接器安装（或长期走 gnu target）；pdfium 渲染 29 页补测（预期 < 2 s）。
- **实测基线**（实现时的性能预算，全部来自本机 spikes）：渲染 53 s / 10 分钟成片（11.6x 实时）；抠像 512p 8.7 ms/帧；音轨拼接 0.9 s；TTS RTF 0.36（29 页串行约 3–4 分钟）；LibreOffice pptx→pdf 13.4 s（参考值，主路径是 COM）。
- **§12 待确认问题**中 Q1/Q4/Q6 已按 PRD 建议处理（V1.1 / V1.1 / 仅 Windows）；Q2、Q3 的"建议不做"已写入 Out of Scope，若用户最终拍板相反，需回改本 spec 的 Out of Scope 与相应 story。
- **合规**：语音克隆必须先勾选《声音授权确认》才能生成；素材全程本地，仅逐字稿文本与参考音频出网（发往 TTS API）。
- 需求冲突时以 `docs/PRD-MVP.md`（v0.5）为准；本 spec 是其可施工翻译，不引入 PRD 之外的新需求。
